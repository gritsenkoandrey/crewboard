# Crewboard

[English version](README.md)

Локальное настольное приложение для проектов, задач и Markdown-документов.
Данные хранятся обычными файлами в выбранной папке; для работы приложения не нужны
аккаунт, сервер или интернет. Для локальных агентов есть CLI с захватом задач и отчётами.

## Возможности

- Проекты с обложками, переименованием и отдельным путём к исходникам.
- Канбан-доска: **Not started → In progress → Done**, перетаскивание и изменение порядка задач.
- Постоянные коды задач вида `TT-24`, дата последнего изменения, Markdown-описание и условия готовности.
- Цветные метки, фильтрация по любой из выбранных меток или по задачам без меток.
- Архив задач с восстановлением в исходную колонку. Удаление задачи — отдельное действие.
- Несколько документов на проект: создание, переименование и изменение порядка вкладок.
- Подключение внешних `.md`-файлов с редактированием оригинала, без копирования в папку проекта.
- Редактор CodeMirror, просмотр Markdown и режим редактора с превью рядом; автосохранение.
- Обнаружение внешних изменений документов и конфликтов сохранения с сохранением правок в редакторе.
- Общий список людей и агентов, назначение задач, сессии, вопросы и Markdown-отчёты через CLI.
- Переключение **RU / EN** справа в верхней панели и при первом запуске. Выбор сохраняется локально;
  даты и счётчики следуют языку интерфейса. Названия проектов и содержимое документов не переводятся.

Стек: **Tauri 2 / Rust**, **React 19 / TypeScript / Vite**, dnd-kit, CodeMirror и markdown-it.
Текущая конфигурация установщика рассчитана на Windows и NSIS.

## Требования для разработки

- Node.js, совместимый с текущим Vite: `^20.19.0 || >=22.12.0`, и npm.
- Rust stable и Cargo; на Windows — MSVC toolchain.
- На Windows — Microsoft C++ Build Tools с компонентом **Desktop development with C++** и WebView2 Runtime.

Установка системных зависимостей описана в [официальной инструкции Tauri](https://v2.tauri.app/start/prerequisites/#windows).
Эти инструменты нужны для разработки и сборки из исходников.

## Запуск из исходников

Склонируйте репозиторий и откройте терминал в его корне. Все команды ниже выполняются из этой папки.

```bash
npm ci
npm run tauri dev
```

Tauri сам запускает Vite и открывает настольное окно. При первом запуске выберите папку данных.
Установка зависимостей и первая сборка могут требовать доступа к сети.

`npm run dev` запускает только фронтенд на `http://localhost:1420`.
Операции с локальными файлами используют Tauri API, поэтому для полноценной работы нужен `npm run tauri dev`.

## Сборка установщика

```bash
npm run tauri build
```

Команда генерирует иконки из `app-icon.png`, проверяет TypeScript, собирает фронтенд и нативное приложение.
Windows-установщик появится в `src-tauri/target/release/bundle/nsis/`.

Для отдельных проверок:

```bash
npx tsc --noEmit
npx vite build
npm run test:i18n
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

`npm run build` собирает фронтенд с генерацией иконок; `npm run preview` показывает его сборку без нативного окна.

## Первые шаги

1. Выберите папку данных и создайте проект.
2. На вкладке «Доска» добавьте задачи, задайте метки, исполнителей и условия готовности.
3. Через кнопку добавления документов создайте документ или подключите существующий Markdown-файл.
4. Для работы агента выберите папку исходников проекта и следуйте [инструкции по CLI](docs/agent-workflow.ru.md).

Изменения сохраняются автоматически. Описание задачи и текст документа сохраняются примерно через
полсекунды после ввода; накопленные правки также передаются на сохранение при закрытии.
`Ctrl+S` в редакторе Markdown запускает сохранение сразу, `Esc` закрывает панель задачи или открытое меню.

Внешний Markdown-файл редактируется на месте. Отключение его вкладки оставляет оригинал на диске.
Удалённые внутренние документы и проекты перемещаются в корзину Windows.

## Где хранятся данные

Папка данных выбирается в приложении и может находиться отдельно от репозитория и папок исходников.
После переустановки приложения достаточно выбрать существующую папку данных.

Настройка выбранного пути хранится отдельно: на Windows это `%APPDATA%/com.local.tasktrack/config.json`.
Пример заполненной папки данных:

```text
<data-dir>/
  participants.json            общие исполнители
  participants.lock            блокировка списка исполнителей
  projects/
    my-project/
      project.json             название, дата создания, обложка, sourceDir
      board.json               колонки, метки, номера задач, сессии и отчёты
      board.lock               блокировка доски
      documents.json           названия, порядок и пути документов
      doc-<timestamp>.md       внутренний документ
      README.md                документ старого формата, если уже был
      cover-<timestamp>.<ext>  копия обложки
```

Файлы создаются по мере использования возможностей. Новые проекты не получают документ автоматически;
существующий `README.md` подхватывается как «Обзор проекта» при первом чтении списка документов.
Его можно переименовать, как любой другой документ. Все названия отображаются ровно так,
как сохранены, и не зависят от языка интерфейса.

- Имя папки проекта — его постоянный id; переименование меняет отображаемое название.
- `sourceDir` указывает на код проекта. Это отдельный путь, а не папка данных трекера.
- `board.json` содержит `todo`, `inProgress`, `done`, `labels`, `taskPrefix` и `nextTaskNumber`.
  Порядок задач в массиве совпадает с порядком в колонке; архивные задачи остаются в исходной колонке.
- В `documents.json` подключённые документы имеют `externalPath`. Их содержимое остаётся вне папки данных.
- Относительные картинки вроде `![](screens/menu.png)` открываются от папки самого Markdown-файла.

Для резервной копии сохраните папку данных, а также внешние документы и используемые ими картинки.
Встроенной облачной синхронизации нет. Операции с задачами выполняйте через приложение или CLI,
не редактируя `board.json` вручную во время работы.

Приложение и CLI используют межпроцессные блокировки и объединяют независимые изменения доски.
Если одно поле изменено одновременно, приложение сообщает о конфликте и оставляет локальные правки в окне.

Язык хранится в локальном хранилище WebView отдельно от данных проектов. При первом запуске
используется русский для системного языка `ru`, иначе английский. Диагностика Rust и агентского CLI
остаётся на английском при любом языке интерфейса.

## Работа с агентами

CLI собирается отдельно от настольного приложения:

```powershell
npm run agent:build
npm run agent -- --help
```

Для прямого запуска в PowerShell из корня репозитория:

```powershell
$tt = Join-Path (Get-Location).Path "src-tauri/target/debug/crewboard-cli.exe"
& $tt --help
```

В обычных командах stdout содержит JSON, ошибки идут в stderr. CLI использует папку данных из настроек;
другую папку можно передать опцией `--data-dir PATH` перед командой. При запуске через npm
служебные строки npm могут сопровождать вывод CLI.

Порядок работы: **claim → выполнение в sourceDir → report → submit**. Захват возвращает token,
который нужен для отчётов, вопросов и передачи результата. `submit` ставит отметку «Готово к проверке»
и оставляет задачу в In progress; в Done её переводит пользователь после проверки.
Назначение исполнителя и вызовы CLI сами по себе не запускают агента.

Полные примеры команд, передача отчёта через stdin и восстановление прерванной сессии:
[работа с агентами](docs/agent-workflow.ru.md) ([English](docs/agent-workflow.md)).

## Структура кода

| Путь | Что там |
|---|---|
| `src-tauri/src/lib.rs` | Настройки, выбор папки данных, атомарная запись, регистрация команд |
| `src-tauri/src/projects.rs` | Проекты и обложки |
| `src-tauri/src/board.rs`, `board_merge.rs` | Проверка и хранение доски, объединение параллельных правок |
| `src-tauri/src/docs.rs` | Внутренние и внешние документы, порядок вкладок, контроль конфликтов |
| `src-tauri/src/agents.rs`, `agent_cli.rs` | Исполнители, исходники и команды агентского workflow |
| `src-tauri/src/storage.rs` | Межпроцессные блокировки |
| `src-tauri/src/bin/crewboard-cli.rs`, `scripts/crewboard-cli.mjs` | CLI и обёртка для запуска через npm |
| `src/App.tsx`, `src/components/ProjectPage.tsx` | Выбор папки данных, проекты и вкладки документов |
| `src/components/Board.tsx`, `TaskPanel.tsx`, `TaskArchive.tsx` | Доска, окно задачи и архив |
| `src/components/LabelPicker.tsx`, `LabelManager.tsx`, `LabelFilter.tsx` | Метки и фильтрация |
| `src/components/Docs.tsx`, `MarkdownEditor.tsx`, `src/markdown.ts` | Редактор, превью и обработка Markdown |
| `src/taskMetadata.ts`, `src/saveTracker.ts` | Даты и архивирование задач, ожидание сохранений |
| `src/i18n.ts`, `src/locales.ts`, `src/components/LanguageSwitcher.tsx` | Выбор языка, словарь и кнопки RU/EN |
| `docs/agent-workflow.ru.md` | Инструкция для пользователя и локального агента |
